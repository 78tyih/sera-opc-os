# Product Development Policy

> Status: GLOBAL / MANDATORY
> Applies to: all new products, projects, major features, pivots, launches, and scale decisions.

## Rule

Any Agent starting or materially changing a product/project MUST load and follow:

`skills/developing-products/SKILL.md`

Do not skip directly from idea to implementation.

## Required sequence

1. 创始灵感 × 深度调研
2. 交叉评审 × 失败推演
3. 最小验证（MVP / Proof）
4. 市场验证 × 触达与分发 × 可持续性验证
5. 事实决策：扩大 / 调整 / 转向 / 停止

Continuous loop: 观察 → 反馈 → 复盘 → 更新 → 再验证。

## Mandatory evidence before implementation

At minimum, record:
- Core problem and target user
- Founder Thesis
- Reference Map including failure cases
- Wedge
- Key assumptions
- Red-team findings
- Cannot-do list
- Success / adjust / pivot / kill thresholds
- Core MVP hypothesis

If these are missing, the Agent must treat the project as **not ready for full implementation** and keep the work at research/prototype level.

## Governing principle

**先解决一个问题，再谈平台与生态；对证据负责，不对 Idea 忠诚。**
