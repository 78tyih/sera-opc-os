# 销售页面框架设计

## 核心原则

销售页面是产品与用户之间的"最后一公里"。优秀的销售页面设计不是展示"产品有什么功能"，而是回答用户心中的一个问题——"这个产品能帮我解决什么问题？"。销售页面的框架设计遵循"先理解、后说服"的原则，通过结构化的信息层级，引导用户从"好奇"到"渴望"再到"行动"。

---

## 为什么有效

### 1. 决策心理学
用户在购买决策中经历"认知-情感-行动"三个阶段。销售页面必须按这个顺序设计：先用逻辑让用户"理解"产品价值，再用情感触发"想要"的冲动，最后用清晰的行动召唤引导"购买"。

### 2. 认知流畅性
当信息以一种易于处理的格式呈现时，用户会感到"更舒服"，并倾向于将这种舒适感转移到产品本身。好的销售页面框架降低认知负荷，让用户更容易理解价值，从而更容易做出购买决定。

### 3. 异议预防
优秀的销售页面不是等到用户提出异议再回应，而是通过结构化的信息排布，在用户产生疑问之前就主动解答。这种"预期式设计"减少了用户的决策阻力。

## 核心销售页面框架

### 1. AIDA 模型

AIDA 是最经典的销售页面框架，适用于大多数产品：

| 阶段 | 目的 | 设计实现 | 页面位置 |
|------|------|---------|---------|
| Attention（注意） | 吸引注意力 | 大标题 + 震撼视觉 + 关键数据 | Hero 区域 |
| Interest（兴趣） | 激发兴趣 | 问题陈述 + 痛点分析 + 故事 | 上方内容区 |
| Desire（渴望） | 创造渴望 | 解决方案展示 + 社会认同 + 案例 | 中部内容区 |
| Action（行动） | 引导行动 | 清晰的 CTA + 紧迫感 + 风险消除 | 页面底部 + 浮动按钮 |

```html
<!-- AIDA 框架的 Hero 区域 -->
<section class="hero">
  <h1 class="hero-title">
    <!-- Attention: 大标题，直击核心价值 -->
    从今天起，告别低效的重复工作
  </h1>
  <p class="hero-subtitle">
    <!-- Interest: 引发共鸣的痛点描述 -->
    我们的 AI 自动化工具将你的工作效率提升 10 倍，
    让你专注于真正重要的事情。
  </p>
  <div class="hero-cta">
    <!-- Action: 清晰的行动召唤 -->
    <button class="btn-primary">免费开始使用</button>
    <span class="hero-trust">无需信用卡 · 30 天免费试用</span>
  </div>
</section>
```

### 2. PAS 框架

PAS（Problem-Agitate-Solution）框架在解决具体痛点的销售页面中效果显著：

| 步骤 | 目的 | 文案策略 | 设计策略 |
|------|------|---------|---------|
| Problem（问题） | 识别用户痛点 | "你是否也面临这个问题？" | 使用用户画像图片，引发共鸣 |
| Agitate（激化） | 放大痛点影响 | 描述不解决痛点的后果 | 使用对比、数据，强化紧迫感 |
| Solution（解决） | 提供解决方案 | 展示产品如何解决痛点 | 功能截图 + 数据对比 + 案例 |

**PAS 设计示例**：

```
问题区域：
  - 标题："你是不是也遇到过这些问题？"
  - 痛点列表：每个痛点带图标 + 简短描述
  - 视觉：灰色调，传达"问题"的感觉

激化区域：
  - 标题："如果不解决，会怎样？"
  - 数据展示："团队每年因低效沟通损失 200+ 小时"
  - 视觉：红色/橙色元素，增加紧迫感

解决区域：
  - 标题："让我们来帮你解决"
  - 产品截图 + 功能亮点
  - 视觉：明亮、积极的色调，传达"解决方案"
```

### 3. 功能-利益映射（Feature-Benefit Mapping）

用户不关心功能，只关心"这个功能对我有什么用"。

| 功能 | 利益映射 | 设计展示 |
|------|---------|---------|
| AI 自动分类邮件 | 每周节省 3 小时的处理邮件时间 | 标题："每周多出 3 小时做真正重要的事" |
| 实时数据分析面板 | 在任何时间了解业务状况 | 标题："你的业务，一目了然" |
| 一键分享功能 | 团队成员无需培训即可上手 | 标题："无需培训，5 分钟上手" |

**设计原则**：
- 每个功能展示都包含"功能 + 利益"两个层次
- 利益在前，功能在后（用户先看到"为什么重要"，再看到"是什么"）
- 使用"所以..."句式连接功能和利益（"AI 自动分类邮件，所以你每周可以节省 3 小时"）
- 利益可视化：使用图标、插画或动画展示利益，而非纯文字

### 4. 异议处理区

```css
/* 异议处理：FAQ 样式 */
.objection-section {
  max-width: 720px;
  margin: 3rem auto;
  padding: 2rem;
}

.objection-item {
  border-bottom: 1px solid #eee;
  padding: 1rem 0;
}

.objection-question {
  font-weight: 600;
  cursor: pointer;
  display: flex;
  justify-content: space-between;
  align-items: center;
}

.objection-answer {
  color: #666;
  line-height: 1.6;
  margin-top: 0.5rem;
  display: none;
}

.objection-item.open .objection-answer {
  display: block;
}
```

**常见异议及处理方式**：
- **价格异议**："为什么这么贵？" → 展示 ROI 计算、按使用量拆分
- **信任异议**："这个产品安全吗？" → 展示安全认证、客户案例
- **能力异议**："这个产品真的有用吗？" → 展示案例数据、效果对比
- **时间异议**："我没时间学习" → 展示"5 分钟上手"的引导流程
- **替代品异议**："我用另一个工具已经够了" → 展示差异化功能对比

### 5. 保证/担保展示

```css
/* 担保展示 */
.guarantee-badge {
  display: flex;
  align-items: center;
  gap: 1rem;
  padding: 1.5rem;
  background: #f8f9fa;
  border-radius: 12px;
  margin: 2rem 0;
}

.guarantee-icon {
  font-size: 2.5rem;
  flex-shrink: 0;
}

.guarantee-text {
  font-size: 0.9rem;
  color: #555;
  line-height: 1.5;
}
```

**担保设计原则**：
- 担保应该具体（"30 天无条件退款"而非"满意保证"）
- 担保应该显眼，放在 CTA 附近
- 担保应该低门槛（"无需理由，全额退款"）
- 担保应该消除用户的最大担忧

### 6. 紧迫性设计

| 紧迫性类型 | 设计方式 | 注意事项 |
|-----------|---------|---------|
| 限时折扣 | 倒计时器 | 必须真实，过期后不再展示 |
| 限量供应 | 库存指示器 | 使用真实库存数据 |
| 限时优惠 | 价格标签 | 展示原价和折扣价对比 |
| 早鸟价格 | 阶梯价格 | 显示"价格上涨时间" |
| 名额限制 | 剩余名额展示 | "仅剩 5 个名额" |

### 7. CTA 定位策略

```css
/* 浮动 CTA 栏 */
.sticky-cta {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  background: #fff;
  padding: 1rem;
  box-shadow: 0 -4px 20px rgba(0,0,0,0.1);
  z-index: 100;
  display: flex;
  justify-content: center;
  gap: 1rem;
  align-items: center;
}
```

**CTA 放置原则**：
- Hero 区域：主要 CTA，最显眼
- 每个关键模块后：次级 CTA，方便"即看即点"
- 页面底部：最终 CTA，配合担保和紧迫性信号
- 浮动 CTA：长页面滚动时固定显示
- 侧边栏 CTA：桌面端额外入口

## 销售页面的结构模板

```
1. HERO 区域
   - 震撼标题（核心价值主张）
   - 副标题（利益陈述）
   - 主 CTA 按钮
   - 社会认同（Logo 墙）

2. 痛点/问题区域
   - 用户痛点列表
   - 痛点导致的后果

3. 解决方案区域
   - 产品功能展示
   - 功能-利益映射
   - 截图/演示视频

4. 社会认同区域
   - 用户评价
   - 客户案例
   - 数据统计

5. 差异化区域
   - 竞品对比
   - 独特卖点

6. 异议处理区域
   - FAQ
   - 担忧解答

7. 最终 CTA 区域
   - 担保展示
   - 紧迫性信号
   - 主 CTA 按钮
```

## 示例

### Apple 产品页面
- Hero 区域：大标题 + 产品全幅图片，极简设计
- 功能展示：每个功能独立一个模块，利益优先
- 对比：使用"比上一代快 X 倍"的简单对比
- 定价：简洁的价格展示 + 分期选项
- 无紧迫性策略（Apple 不做限时折扣，保持品牌高端感）

### Notion 销售页面
- 使用"模板展示"代替"功能列表"——用户看到"用 Notion 可以做什么"
- 案例展示按行业分类，增强相关性
- 使用"从 xxx 迁移"的功能，降低用户转换成本感知
- 评价直接嵌入在功能展示中，提供即时社会认同
- 定价页展示"免费开始"而非"立即购买"

---

## 何时使用

- 产品的核心销售页面
- 新功能发布的推广页面
- 营销活动的落地页
- 产品定价和订阅页面
- 需要引导用户完成购买决策的任何页面

## 何时不宜使用

- 用户已经明确购买意图的页面（如结账页）——不要再用销售话术干扰决策
- 面向已有用户的更新说明页——用户需要的是"这是什么变化"而非"为什么买"
- 品牌形象页面（如"关于我们"）——应以叙事为主，而非销售导向
- 用户自助服务页面——应以效率为导向，而非说服
- 法律合规页面（如服务条款、隐私政策）——不需要销售框架
