# Design Principle: AI Product Design

> 知识类型：design-principle
> 版本：1.0.0
> 适用：AI 产品 / 智能助手 / 机器学习平台

---

## 核心原则

**AI 产品的设计核心是"可理解性"，不是"智能感"。**

用户不需要知道你的模型有多强，他们需要知道：
1. 这个 AI 能做什么（能力边界）
2. 使用它需要什么（门槛）
3. 结果是否可靠（可信度）

---

## AI 产品设计特性

### 1. 能力可视化

AI 的能力是抽象的。设计必须让它"可见"：

```
- 输入 → 输出示例（Before/After）
- 实时演示（Demo 区域）
- 能力列表（具体可做 X、Y、Z）
- 限制说明（不能做什么）
```

### 2. 降低使用门槛

```
- 不需要 prompt engineering
- 自然语言交互优先
- 预设场景 / 模板引导
- 渐进式复杂度
```

### 3. 建立可信度

```
AI 产品的信任问题：
- 结果是否准确？
- 数据是否安全？
- 会不会出错？

解决方案：
- 展示准确率 / 案例
- 隐私说明
- 人工兜底
- 错误处理透明
```

## AI 产品布局策略

### 推荐结构

```
01 Hero：一句话说明 + 演示区域
02 能力展示：具体能做什么
03 技术可信：数据安全 + 准确率
04 使用场景：谁在用、怎么用
05 定价（如有）
06 CTA
```

### 演示区域设计

```
Demo 是 AI 产品最重要的转化工具。

要求：
- 首屏或接近首屏可见
- 展示真实输入 → 输出
- 可交互（非截图）
- 加载时间 < 2s
```

## AI 产品色彩策略

### 推荐色板

```
主色：蓝色 / 紫色系 → 科技感、智能
辅色：白色 / 浅灰 → 简洁、聚焦
强调色：渐变蓝紫 → AI 识别度
```

### 避免

```
❌ 过于冷峻的深色 → 距离感
❌ 过于花哨的渐变 → 不专业
❌ 低对比度 → 可读性差
```

## AI 产品文案策略

### Headline 模式

```
结构：[能力] + [结果] + [简单]

示例：
"用 AI 生成你的产品页面"（能力 + 结果）
"3 分钟，从想法到页面"（简单 + 结果）
"你的 AI 设计总监"（角色化）
```

### 避免

```
❌ 过度承诺："完全自动""无需人工"
❌ 技术炫耀："基于 GPT-4o + RAG"
❌ 模糊描述："智能解决方案"
```

## 检查清单

- [ ] 用户能否在 5 秒内理解 AI 能做什么？
- [ ] 是否有可交互的 Demo 或示例？
- [ ] 能力边界是否清晰？（能做什么 + 不能做什么）
- [ ] 是否建立了可信度？（数据安全 / 准确率）
- [ ] 使用门槛是否足够低？
- [ ] 是否有人工兜底方案？
