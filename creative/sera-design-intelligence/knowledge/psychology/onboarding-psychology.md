# 引导流程心理学

## 核心原则

引导流程（Onboarding）是用户从"初次接触"到"体验核心价值"的完整旅程。优秀的引导不是教用户如何使用产品，而是帮助用户尽快到达"啊哈时刻"（Aha Moment）——即用户第一次感受到产品核心价值的时刻。引导设计的核心原则是"渐进式披露"——在用户需要的时候，给他们需要的信息，而不是一次性倾倒所有功能。

---

## 为什么有效

### 1. 认知负荷理论（Cognitive Load Theory）
人类的工作记忆容量有限，同时只能处理约 3-5 个信息块。初次使用产品时，用户需要同时理解界面布局、功能含义、操作方式和使用场景，很容易超载。好的引导将认知负荷分散到多个步骤中，每一步只聚焦一个信息点。

### 2. 蔡格尼克效应（Zeigarnik Effect）
人对未完成的任务的记忆比已完成的任务更深刻。进度指示器利用了这个效应——用户看到"3/5 已完成"时，会倾向于完成整个流程，因为未完成的状态在大脑中保持"激活"。

### 3. 赋权感（Empowerment vs. Overwhelm）
引导的核心矛盾是"指导 vs. 探索"。过多的强制引导会让用户感到被控制，过少则会让用户感到迷茫。优秀的引导在提供指导的同时，始终保留"跳过"和"以后再说"的选项，给用户控制感。

## 引导设计模式

### 1. 首次运行体验（First-Run Experience）

| 模式 | 描述 | 适用场景 | 关键设计原则 |
|------|------|---------|-------------|
| 空状态引导 | 利用空状态页面展示"下一步操作" | 任何需要用户主动操作的产品 | 空状态不是空白，而是"开始的地方" |
| 功能亮点 | 展示 3-5 个核心功能的截图/动画 | 功能丰富的产品 | 每个亮点不超过 10 个字 |
| 互动教程 | 引导用户完成第一个操作 | 工具型产品 | 让用户真正操作，不只是看 |
| 视频引导 | 1-2 分钟的产品介绍视频 | 复杂产品 | 控制在 90 秒内 |
| 渐进式引导 | 在使用过程中逐步展示功能 | 任何产品 | 在用户需要时提供帮助 |

### 2. 渐进式披露（Progressive Disclosure）

```css
/* 渐进式披露的遮罩层设计 */
.onboarding-overlay {
  position: fixed;
  inset: 0;
  background: rgba(0, 0, 0, 0.5);
  z-index: 1000;
}

.onboarding-highlight {
  position: relative;
  z-index: 1001;
  box-shadow: 0 0 0 4px #fff, 0 0 0 8px rgba(66, 133, 244, 0.4);
  border-radius: 8px;
}

.onboarding-tooltip {
  position: absolute;
  background: #fff;
  border-radius: 12px;
  padding: 1rem;
  box-shadow: 0 8px 32px rgba(0,0,0,0.15);
  max-width: 320px;
  z-index: 1002;
}
```

**渐进式披露原则**：
- **一次一个**：每次只展示一个信息点或一个操作
- **相关性**：在用户即将使用某个功能时再展示该功能的引导
- **可跳过**：始终提供"跳过"或"稍后"选项
- **可回忆**：引导消失后，用户应该知道如何再次找到帮助

### 3. 认知负荷降低策略

| 策略 | 实现方式 | 效果 |
|------|---------|------|
| 分步式引导 | 将复杂操作拆分为 3-7 步 | 降低单步认知负荷 50%+ |
| 默认值填充 | 预填推荐设置 | 减少决策疲劳 |
| 模板化 | 提供预设模板 | 从零开始到填充模板，转化率提升 3x |
| 示例数据 | 展示"填充后的样子" | 降低想象成本 |
| 即时反馈 | 每个操作立即有视觉反馈 | 强化学习效果 |

### 4. 动机时机（Motivation Timing）

用户在不同阶段的动机不同，引导内容需要匹配当前动机水平：

```
动机水平
  ↑
  |  [兴奋期]  → 展示愿景和核心价值
  |  [探索期]  → 提供互动引导，快速上手
  |  [实用期]  → 展示高级功能和工作流
  |  [精通期]  → 提供快捷键、技巧和自动化
  +--------------------------------→ 时间
```

**各阶段设计策略**：
- **兴奋期（前 30 秒）**：展示产品核心价值，不要讲功能细节
- **探索期（1-5 分钟）**：引导完成第一个"完整任务"而非"完整功能"
- **实用期（第 1 天-第 1 周）**：通过邮件/推送提示下一个"最佳实践"
- **精通期（1 周后）**：提供进阶技巧和效率工具

### 5. 进度指示器设计

```html
<!-- 进度指示器 -->
<div class="step-indicator">
  <div class="step active">1</div>
  <div class="step-line"></div>
  <div class="step">2</div>
  <div class="step-line"></div>
  <div class="step">3</div>
  <div class="step-line"></div>
  <div class="step">4</div>
</div>
```

**进度指示器设计原则**：
- 展示总步骤数（"步骤 2/5"）比仅展示进度条让完成率提升 20%
- 步骤名称（如"设置资料 > 邀请团队 > 完成"）比纯数字更有方向感
- 已完成步骤用绿色/勾号标记，提供成就感
- 避免超过 7 步，超过 7 步时考虑合并或分组
- 允许用户随时"保存并退出"——减少一次性完成的心理压力

### 6. 空状态设计

空状态（Empty State）不是"什么都没有"，而是"邀请开始"。

```css
/* 空状态设计 */
.empty-state {
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  padding: 4rem 2rem;
  text-align: center;
}

.empty-state-icon {
  font-size: 3rem;
  margin-bottom: 1rem;
  opacity: 0.4;
}

.empty-state-title {
  font-size: 1.25rem;
  font-weight: 600;
  margin-bottom: 0.5rem;
}

.empty-state-description {
  color: #666;
  margin-bottom: 1.5rem;
  max-width: 400px;
}
```

**空状态设计原则**：
- 永远不要展示空白页面或报错界面
- 提供明确的"下一步操作"按钮
- 展示示例数据或"填充后的样子"
- 使用友好的文案，避免"暂无数据"这样的技术术语
- 插画或图标增加情感温度

## 引导流程的 A/B 测试关键指标

| 指标 | 目标 | 常见优化方向 |
|------|------|-------------|
| 引导完成率 | > 70% | 减少步骤数、简化信息、优化进度指示 |
| 到达 Aha 时刻时间 | < 5 分钟 | 重新排序步骤、移除非关键步骤 |
| 引导后 7 日留存 | > 40% | 改进引导后的"第二天"体验 |
| 首次核心操作完成率 | > 60% | 改善引导中的互动操作设计 |
| 引导跳过率 | < 20% | 降低"跳过按钮"的视觉权重，或增加引导价值 |

## 示例

### Duolingo 的引导流程
- 第一屏直接进入互动练习，而非功能介绍
- 使用游戏化元素（星星、进度条、连续打卡）激励用户
- 渐进式披露：每完成一个关卡才解锁新功能
- 空状态设计：空的进度条激励用户"开始你的第一课"
- 即时反馈：每个答案后立即显示正确/错误

### Notion 的模板引导
- 注册后直接进入模板选择，而非空白页面
- 提供"团队"、"个人"、"学生"等不同场景的模板
- 模板填充后，用户立刻感受到"这是一个完整的工作空间"
- 引导过程不打断用户使用，而是"在需要时出现"
- 使用"What's New"面板在后台提供持续引导

## 何时使用

- 任何新用户首次使用产品时
- 产品功能复杂，用户需要学习才能上手
- 目标是提高用户激活率和留存率
- 产品有多个关键功能需要用户依次发现
- 用户需要完成特定设置才能体验核心价值

## 何时不宜使用

- 产品极其简单，用户可以直接上手（如计算器、时间工具）
- 用户是专家用户或已有使用类似产品的经验（如开发者工具）
- 引导流程本身比产品使用更复杂——简化产品而非增加引导
- 用户通过其他渠道已经了解产品（如从演示视频来的用户）
- 高频返访问用户——每次登录都展示引导会令人厌烦
